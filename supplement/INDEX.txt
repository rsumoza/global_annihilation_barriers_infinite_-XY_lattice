STATUS AND SCOPE
The repository address was supplied by the author. Release publication,
the resolved source commit and remote asset downloads are not yet verified.
All Release/asset URLs below are configured destinations until publication.
No public DOI or actual journal submission is asserted.
The fixed certificate treats a dipole at separation 12 on the infinite
square exact-cosine XY lattice, with all admissible strong-energy paths.
Its barrier satisfies 0.00567867 < B_ann < 0.00570116. The explicit infinite
input class reuses that communication height and includes noncompact
block-generated perturbations with a controlled tail. Arbitrary XY
configuration completeness remains open. The general refinement interface
is proved constructively but is not implemented as a general program.

REQUIRED ENVIRONMENT
Python 3 with its standard library suffices for the rational checks.
Full replay additionally requires g++ and the environment accepted by
checks/verify_supported_environment.py: reviewed x86_64 Linux, 64-bit
long-double significand, little-endian binary64 and round-to-nearest.
Install a normal supported C++ build toolchain. Do not force acceptance of
a failed environment preflight or compile with unsafe arithmetic options.
The optional figure script uses NumPy and Matplotlib. Article compilation
uses pdflatex and the standard TeX Live packages listed in README.txt.

STEP 1. OBTAIN THE FROZEN SOURCE SNAPSHOT
After publication, either unpack S1 or clone and check out the exact tag:
  git clone https://github.com/rsumoza/global_annihilation_barriers_infinite_-XY_lattice.git xy-siads
  cd xy-siads
  git checkout --detach siads-v7-2026-10-22
  git rev-parse HEAD
Record the full commit SHA with your results. GitHub's automatic source-code
ZIP contains this tree but does not contain the large Release assets.
Validate the S1 ZIP using the separately supplied SOURCE_SNAPSHOT.sha256.
Inside the extracted GitHub_Repository/ directory (or tagged Git checkout):
  sha256sum -c MANIFEST.sha256

STEP 2. OBTAIN AND VERIFY S2-S4
From the S1 source root:
  python3 checks/download_release_assets.py --assets-dir ../release_assets
  python3 checks/verify_release_assets.py --assets-dir ../release_assets
For manual downloads, use the exact filenames above and the same verifier.
A failure is an integrity or availability error, not a mathematical result.
The historical five S3_Conexion volumes are only an alternative transport:
checks/reconstruct_connection.py reconstructs the original S3 bytes. All five
parts are needed. Do not substitute one volume for the full S3 archive.

STEP 3. RUN THE SMALL CHECKS
  python3 checks/verify_supported_environment.py --output /tmp/xy-environment.json
  python3 checks/verify_robustness_constants.py
  python3 checks/verify_green_tail_budget.py
  python3 checks/verify_infinite_class.py --self-test --output /tmp/xy-infinite-class.json
Expected: successful exit and PASS reports. The last checker exercises four
finite-prefix examples and rejects eight deliberate changes. It does not
compute arbitrary nontrivial fibers or execute the general refinement proof.

STEP 4. EXTRACT THE THREE ORIGINALS INTO A NEW WORK DIRECTORY
From the S1 source root, create a new sibling directory with ample free space:
  mkdir ../xy_replay_work
  unzip ../release_assets/XY_Separacion_Global_Reproducible_2026-10-19.zip -d ../xy_replay_work
  unzip ../release_assets/XY_Conexion_Global_Reproducible_2026-10-19.zip -d ../xy_replay_work
  unzip ../release_assets/XY_Optimalidad_Extension_Reproducible_2026-10-19.zip -d ../xy_replay_work
The extracted roots must be siblings named xy_global_separator,
xy_global_connection and xy_optimality_extension. Use a fresh directory,
not the archived proof_record tree. The compressed originals total 729379521
bytes; extraction and new outputs require additional disk space.

STEP 5. REPLAY THE COMPLETE CERTIFICATE
  cd ../xy_replay_work/xy_optimality_extension
  python3 verify_optimality.py --separator-package ../xy_global_separator --connection-package ../xy_global_connection --output results_fresh --workers 2
Use a previously absent output directory and no options that reuse validated
results. Frozen candidate arrays are inputs; previous validated outputs must
not become premises. Expected final status:
  FRESH_OPTIMAL_ANNIHILATION_BARRIER_PASS
The archived 21 October 2026 replay took 737.33 seconds and checked 548
output hashes on its documented machine. This is an observation, not a
runtime guarantee. Inspect all phase statuses and skipped-check fields;
compare the certified bounds and mathematical conclusions. Build metadata
or formatting can legitimately differ between environments.

STEP 6. COMPARE RECORDS AND INTERPRET THE RESULT
The archived full replay is in proof_record/ in S1; dated supplementary
diagnostics are in verification_notes/. Keep new outputs separate.
verify_robustness_constants.py accepts --certificate-root to examine a new
certificate tree; consult its --help for that interface. The optional binary
path audit is documented in README.txt. Compilation commands for the article
and companion are also in README.md/README.txt.

TRUST BOUNDARY
Replay uses the original interval implementation. It is not a formally
verified proof or a second independent interval engine. A generic NaN
rejection weakness and historical export issues remain documented; protected
fixed-input diagnostics and exact rational comparisons accompany the record.
No mathematical discrepancy was detected in the targeted audit. The new
infinite-class check verifies exact constants and finite prefixes; the
general arbitrary-precision refinement construction is a theorem in the
article and has no general implemented user interface in this snapshot.
