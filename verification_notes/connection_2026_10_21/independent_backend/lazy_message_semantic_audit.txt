Lazy-message guard optimization: read-only semantic audit
21 October 2026

Compared stage2/saddle/engine.cpp with stage2/saddle_fast/engine.cpp,
including the supplied engine_lazy_messages.patch. Also compared both
certify.cpp copies byte for byte. No heavy numerical job was executed.

Result
------
The only changes are one added helper and nine dispatch substitutions:
  static void guard_need(bool condition,const char* message) {
      if(!condition) throw std::runtime_error(message);
  }

The nine substituted calls are precisely the injected diagnostic guards:
  dn: finite argument and finite nextafter result (2);
  up: finite argument and finite nextafter result (2);
  scalar and endpoint interval constructors (2);
  congruence dimensions, finite/ordered A and finite V inputs (3).

Removing that one helper definition and changing guard_need( back to need(
produces exact byte equality with the previous guarded engine text. Thus the
predicates, their evaluation sites, error-message bytes, counters, increments,
return expressions and every numerical expression are unchanged. All 70
original frozen engine need() call sites remain untouched. The two certify.cpp
files are byte-identical. No guard was disabled or made conditional on NDEBUG.

The change eliminates construction/destruction of a temporary std::string
on successful diagnostic checks. On failure both routes throw std::runtime_error
with the same message bytes and are caught by the existing rejection handler.
This is equivalence of the numeric/rejection contract, not an assertion that
allocation-failure behavior or every resource-level C++ observation is identical.
The old code could allocate before even entering need(); the new code postpones
message allocation until failure.
